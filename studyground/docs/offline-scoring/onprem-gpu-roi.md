# 온프렘 GPU 경제성 — 결론이 뒤집혔다

← [[offline-scoring-moc]] · 대상은 [[scoring-options#04 · 캠퍼스 사설망]] · 구조는 [[campus-architecture]]

> [!danger] 정정
> 04번을 “GPU 한 대면 된다”고 가볍게 말하면 안 된다. **양쪽에 같은 음성 스택을 물리는 순간 숫자가 뒤집힌다.**

## 프레이밍이 답을 바꿨다

```
voice_mode      breakeven    36mo saving   무엇을 비교하나
isolate_llm         never       $-51,893   Gemma-4 로컬 vs 호스팅 LLM  ← 실제 질문
split             month 4       $241,496   LLM + ElevenLabs-vs-Kokoro 가 섞임
voice_cloud         never       $-51,893   LLM만, 양쪽 다 호스팅 음성
```

처음 모델은 클라우드 쪽에만 호스팅 TTS를 물리고 로컬에는 Kokoro를 공짜로 줬다. 그래서 “36개월 $241k 절감, 4개월 회수”가 나왔는데 — **그 절감의 97%는 GPU와 무관하고 ElevenLabs를 안 쓴 덕분이었다.**

재현: `python3 roi/roi_model.py --compare-framings`

## 정직한 프레이밍의 월 비용

| 항목 | 클라우드 | 로컬 GPU |
|---|---:|---:|
| LLM 추론 | $104 | **$575** |
| 사람 재채점 | $3,659 | $3,659 |
| 합계 (capex 제외) | **$3,763** | **$4,234** |

> [!failure] 클라우드 추론비가 로컬 GPU 전기요금보다 싸다
> $104/월 대 **전기요금만 $215/월**. capex $31,500은 계산에 들어가기도 전이다.
> 몬테카를로 2,000회 중 **36개월 안에 회수하는 경우는 0%**.
> 호스팅 단가가 **약 17배**(입력 $5.06 / 출력 $20.24 per Mtok — 대략 프런티어 모델 가격대) 올라야 비로소 뒤집힌다.

## 그래서 어떻게 쓰나

> [!important] 품의서의 근거는 “데이터 주권 + 오프라인 내구성”
> 밴드 채점에 프런티어급 모델이 정말 필요하다면 GPU 구매가 정당화되고, 중급 모델로 충분하다면 비용 논리로는 정당화되지 않는다.
> **가격 검증 한 번에 무너지는 비용 논리는 심사를 통과하지 못한다.**

## 부수적으로 드러난 것 둘

**GPU 처리량은 제약이 아니다.** 1대가 월 599M 출력 토큰을 처리하는데 수요는 78M이다. 대수는 전적으로 “캠퍼스당 1대” 이중화 하한이 결정한다. 처리량을 반토막 내도 결과가 같다.

**사람 재채점이 클라우드 총비용의 97%다.** 양쪽이 똑같이 내므로 구매 결정과는 무관하지만, 비용을 실제로 줄이고 싶다면 건드릴 곳은 GPU가 아니라 `human_review_rate`(현재 12%)다. 그리고 그 비율은 채점 신뢰도(QWK)가 결정한다.

## 반드시 교체해야 하는 가정

`roi/params.json` 에서 `SOURCE:QUOTE` 로 표시된 값은 전부 추정치이며 **측정값이 아니다.**

| 필드 | 왜 중요한가 |
|---|---|
| `cloud.input_per_mtok` / `output_per_mtok` | 구매 결정을 단독으로 뒤집는다 |
| `usage.active_student_ratio` (0.75) | 파일럿에서 계측해 교체할 것 |
| `staff.human_review_rate` (0.12) | 총비용의 대부분 |
| `local.throughput.tokens_per_second_output` | 현재 부하에선 무관하나 확장 시 필요 |

몬테카를로의 분포도 가정이지 관측이 아니다. 점추정의 타당성을 검증하지 않으며, 명시된 불확실성이 함의하는 폭을 정량화할 뿐이다.
