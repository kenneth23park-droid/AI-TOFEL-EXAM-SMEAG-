# 성적 세트 — 여러 번 친 시험에서 한 벌을 고른다

학생은 선생님의 동의를 받아 시험을 다시 친다. 리딩만 다시 치기도 하고, 스피킹만 다시
치기도 한다. 그때마다 `sg_results` 에 줄이 하나씩 늘고 `attempt_no` 로 회차가 갈리지만,
**성적표에 적을 "한 벌"은 어디에서도 만들어지지 않는다** — 8월 3일 응시의 리딩과
8월 9일 응시의 스피킹은 서로 다른 행이기 때문이다.

이 문서가 말하는 것이 그 한 벌이다.

## 누가 무엇을 하는가

| | 하는 일 |
|---|---|
| 선생님 | 다시 치는 것을 허락한다. 이름이 성적 세트에 **동의의 기록**으로 남는다. |
| 관리자 | 영역마다 회차를 하나씩 골라 확정한다. 저장은 관리자만 된다(RLS `sg_is_admin`). |
| 학생 | smeag.com 성적 조회에서 확정된 세트를 본다. 고칠 수는 없다. |

선생님 계정으로 `admin-score-sets.html` 을 열면 화면은 뜨지만 저장은 서버가 거절한다.
화면의 안내는 그 사실을 미리 말해 줄 뿐이고, 경계는 언제나 RLS 다.

동의 없는 성적 세트는 만들 수 없다 — 표에 제약이 걸려 있다
(`approved_by is not null or approved_name <> ''`).

## 「내 최고 점수」와 무엇이 다른가

smeag.com 의 「내 최고 점수」는 영역별 최고를 **기계가** 집는다. 참고값이다.
성적 세트는 **사람이** 고른 성적이다. 그래서 화면에서도 성적 세트가 위에 온다.

관리자 화면의 첫 제안도 "가장 높은 회차"가 아니라 "가장 최근에 점수가 나온 회차"다.
성적은 잘 본 것을 모으는 일이 아니라 어느 응시를 성적으로 삼을지 정하는 일이고,
그 판단을 화면이 대신하면 사람이 고른 것처럼 보이는 자동 선택이 되어 버린다.

## 점수를 복사하지 않는다

저장되는 것은 `picks` — "어느 영역을 어느 응시(session)에서 가져오는가" 뿐이다.

```json
{ "reading":  { "session": "…", "set_code": "SET 9", "attempt_no": 1 },
  "listening":{ "session": "…", "set_code": "SET 9", "attempt_no": 1 },
  "writing":  { "session": "…", "set_code": "SET 9", "attempt_no": 2 },
  "speaking": { "session": "…", "set_code": "SET 9", "attempt_no": 2 } }
```

그래서 나중에 선생님이 라이팅 점수를 고치면 성적 세트도 따라 고쳐진다 — 성적표가 옛
점수를 들고 굳는 일이 없다. 확정하던 순간의 밴드는 `snapshot` 에 따로 남지만 화면은
쓰지 않는다(감사용이다: "그때 무엇을 보고 확정했는가").

밴드 계산은 어디서나 한 벌이다 — `sg2/assets/sg-band.js`. 합치는 규칙만 여기서 더한다:
객관식(R·L)은 고른 응시의 `by_section` 에서, 산출형(W·S)은 고른 응시의 `sg_task_scores`
행에서 온다. 종합은 합쳐진 **네 밴드의 평균**이지, 어느 한 응시의 종합이 아니다.

## 지우지 않는다

잘못 만든 세트는 `voided_at` 으로 무효가 되고 자리에는 남는다. `delete` 정책을 두지
않았으므로 지우는 길은 `service_role` 뿐이다 — `sg_results.hidden`, `sg_archives` 와
같은 원칙이다.
