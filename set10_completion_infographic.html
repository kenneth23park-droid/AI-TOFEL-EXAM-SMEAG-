SET 10 Visibility Fix

왜 테스트에서 문제가 안 보였는가

문제는 세트 10 본문이 아니라 set 선택 규칙이었습니다. 이전 로직은 SET10을 set1로 잘못 해석할 수 있었고, 그 결과 올바른 주소로 들어가도 set 10 문제지가 아니라 다른 세트나 빈 화면이 보일 수 있었습니다.
수정 완료: SET10 지원 추가 핵심 원인: testId 분기 누락 올바른 URL: ?set=set10

세트 선택 흐름
시험 화면은 URL에서 세트를 고른 뒤, 그 세트의 문제지 파일을 불러옵니다. 아래처럼 흘러가야 `SET10`이 정상적으로 보입니다.
1. URL 입력

exam-runtime.html?set=set10&testId=SET10

→
2. 세트 선택

currentSetId()가 set=set10을 우선 사용

→
3. 문제지 렌더

window.SMEAG_SET10을 읽어 Reading/Listening/Writing/Speaking을 표시

고치기 전
`SET10`이 `set1`로 내려갈 수 있어, 올바른 주소인데도 다른 세트 화면이 뜨는 문제가 있었습니다.
오인식 가능
고친 후
`SET10`을 명시적으로 `set10`으로 매핑해서, 세트 10 문제지가 바로 보이게 했습니다.
정상 인식
실제 사용
이제 테스트할 때는 `set=set10`을 붙여서 열면 됩니다. `testId=SET10`도 함께 넣으면 혼동이 줄어듭니다.
권장 주소
수정 요약
항목내용
원인 `exam-shell.js`의 시험 코드 해석이 `SET10`을 set10으로 처리하지 못함
수정 setFromTestId()에 `SET10` 매핑을 추가
결과 `?set=set10` 또는 `?testId=SET10`에서도 set 10 문제지를 불러올 수 있음
주의
로컬 브라우저가 저장된 세트를 먼저 올려야 하는 경우가 있습니다. 그래도 기본 원칙은 같습니다. 선택한 세트는 다른 세트로 조용히 바뀌지 않아야 하고, `SET10`은 이제 독립적으로 해석됩니다.
