# SMEAG 사설망 AI 채점 스택 — 코드 + ROI 모델

Gemma 4를 캠퍼스 사설망에서 서빙하여 IELTS/TOEFL 라이팅·스피킹을 채점하고,
그 채점을 신뢰할 수 있는지 검증하고, GPU를 사는 게 경제적으로 맞는지 계산하는
스캐폴드입니다.

모든 스크립트는 **의존성 없이(numpy만) 바로 실행 가능**하며, 아래 결과는
전부 실제로 돌려서 확인한 것입니다.

```
smeag-local-ai/
├── serving/        vLLM + Whisper + Kokoro 캠퍼스 노드 구성
├── scoring/        루브릭 시스템 프롬프트, JSON 스키마, 채점 클라이언트
├── qa/             QWK 캘리브레이션(채점 신뢰도), WER 루프백(TTS 음원 QA)
├── roi/            로컬 vs 클라우드 비용 모델
└── data/           생성된 CSV 출력
```

## 빠른 실행

```bash
python3 qa/calibrate.py --selftest              # QWK 구현 검증
python3 qa/calibrate.py --simulate --n 300      # 골드셋 규모 설계
python3 qa/stt_loopback.py --selftest           # 음원 QA 게이트 검증
python3 roi/roi_model.py --compare-framings     # ← 먼저 이것부터 보십시오
python3 roi/roi_model.py --voice isolate_llm    # 전체 비용 리포트
```

## 1. 채점 신뢰도 (qa/)

`metrics.py`는 QWK를 numpy로 직접 구현합니다. 밴드를 half-band 정수(band×2)로
매핑하고, **카테고리 격자를 표본이 아니라 전체 밴드 스케일(1.0–9.0)에 고정**합니다.
표본에서 격자를 뽑으면 밴드 분포가 좁은 골드셋의 kappa가 부풀려져서 데이터셋 간
비교가 불가능해집니다.

자체 검증 결과 (`--selftest`, 전부 통과):

| 검사 | 결과 |
|---|---|
| 동일 채점자 | 1.000000 |
| 독립 채점자 | 0.0388 |
| 일괄 +0.5밴드 편향 | 0.9552 |
| 일괄 +2.0밴드 편향 | 0.5307 (2차 가중이 제대로 벌줌) |
| 격자 이탈(6.3) / 범위 이탈 입력 | ValueError |

**골드셋 규모:** ±0.05 신뢰구간 폭을 얻으려면 **n=441**이 필요합니다.
앞서 이야기한 300건으로는 CI 폭이 대략 ±0.06이라, 점추정 0.72가 나와도
0.70 게이트를 확실히 넘었다고 말할 수 없습니다.

시뮬레이션(n=300, 편향 +0.3밴드, 노이즈 SD 0.55) 결과 QWK 0.736, CI [0.681, 0.783].
민감도 스윕에서 읽어야 할 것:

- **노이즈가 지배합니다.** 편향을 0으로 없애도 노이즈 0.75면 TUNE(0.679).
  반대로 노이즈 0.35면 편향 +0.5여도 PASS(0.734).
- 다만 **편향이 고치기 훨씬 쌉니다** — 루브릭 tie-breaking을 낮은 밴드 쪽으로
  조이고 재측정하는 게 파인튜닝보다 먼저입니다.

## 2. 채점 클라이언트 (scoring/)

- **스키마 강제 디코딩** (`guided_json` + xgrammar) — 형식 붕괴가 물리적으로 불가능
- **자기일관성 3회** — 기준별 중앙값 집계, 편차 1.0밴드 초과 시 사람에게 라우팅
- **근거 검증** (`verify_evidence`) — 모든 인용문이 학생 답안에 문자 그대로
  존재하는지 확인. 스택에서 가장 싼 가드인데, 신뢰를 가장 빨리 무너뜨리는
  실패(학생이 쓰지도 않은 문장을 인용)를 잡습니다.
- **IELTS 반올림** — Python 기본 `round()`는 banker's rounding이라 6.25를 6.0으로
  내립니다. IELTS 규칙은 올림이므로 `ielts_overall()`에서 직접 계산합니다.
  (검증: 6.25→6.5, 6.125→6.0)

스피킹 루브릭에는 **PRO(발음) 상한 7**을 걸었습니다. 전사 텍스트로는 모음 질,
강세, 억양을 볼 수 없으므로 8·9를 줄 근거가 없습니다. 발음을 제대로 채점하려면
별도 모델(GOP 또는 Wav2Vec2)이 필요하고, 그건 이 스캐폴드 밖입니다.

## 3. 음원 QA (qa/stt_loopback.py)

렌더된 MP3를 다시 전사해 원본과 비교합니다. WER은 `text_display`가 아니라
**`text_tts`(정규화된 입력 문자열)** 기준입니다 — 화면 표기 기준으로 비교하면
"3:15 pm"을 올바로 읽은 것까지 전부 오류로 잡힙니다.

편집거리를 치환/삭제/삽입으로 분해해서 진단을 분리합니다: **삭제 우세 = 음원 잘림**,
**치환 우세 = 발음 오류**. 고치는 방법이 다르므로 WER 숫자 하나로는 부족합니다.

설계 중 발견해 고친 것: 5% 임계값을 짧은 세그먼트에 그대로 적용하면
10단어짜리 Part 1 질문은 단어 하나만 틀려도 무조건 리젝됩니다(9.1%).
25단어 미만 세그먼트는 절대 오류 개수로 판정하도록 분기했습니다.

## 4. ROI 모델 (roi/) — 결론이 뒤집혔습니다

**먼저 `--compare-framings`를 돌려보십시오.**

```
voice_mode         breakeven    36mo saving   what it compares
isolate_llm            never       $-51,893   Gemma-4 local vs hosted LLM (실제 질문)
split                month 4       $241,496   LLM + ElevenLabs-vs-Kokoro가 섞임
voice_cloud            never       $-51,893   LLM만, 양쪽 다 호스팅 음성
```

처음 모델은 클라우드 쪽에만 호스팅 TTS를 물리고 로컬에는 Kokoro를 공짜로
줬습니다. 그 결과 "36개월 $241k 절감, 4개월 만에 회수"라는 숫자가 나왔는데,
**그 절감의 97%는 GPU와 무관하고 ElevenLabs를 안 쓴 덕분**이었습니다.
음성 스택을 양쪽 동일하게 맞추면 결론이 반대가 됩니다.

정직한 프레이밍(`isolate_llm`)에서 정상 부하 시점 월 비용 구성:

| 항목 | 클라우드 | 로컬 |
|---|---:|---:|
| LLM 추론 | **$104** | **$575** (전기+유지비) |
| 사람 재채점 | $3,659 | $3,659 (양쪽 동일) |
| 합계(capex 제외) | $3,763 | $4,234 |

클라우드 추론 $104/월이 로컬 GPU 3대의 **전기요금($215)보다도 쌉니다**.
capex $31,500은 계산에 들어가기도 전입니다. 몬테카를로 2,000회 중
**로컬이 36개월 안에 회수하는 경우는 0%**입니다.

**가격 경계:** 호스팅 추론 단가가 **약 17배**(입력 $5.06 / 출력 $20.24 per Mtok)를
넘어야 온프렘이 회수됩니다. 이건 대략 프런티어 모델 가격대입니다.

> 즉 밴드 채점에 프런티어급 모델이 정말 필요하다면 GPU 구매가 정당화되고,
> 중급 모델로 충분하다면 비용 논리로는 정당화되지 않습니다.
> **후자라면 품의서에 "비용 절감"이 아니라 "데이터 주권 + 오프라인 내구성"을
> 근거로 쓰셔야 합니다.** 가격 검증 한 번에 뒤집히는 비용 논리는 심사를 통과하지 못합니다.

부수적으로 드러난 것 두 가지:

- **GPU 처리량은 제약이 아닙니다.** 1대가 월 599M 출력 토큰을 처리하는데 수요는
  78M입니다. 대수는 전적으로 "캠퍼스당 1대" 이중화 하한이 결정합니다.
  처리량을 반토막 내도 결과가 동일합니다 — 학생 수가 지금의 8배쯤 되어야
  비로소 의미가 생깁니다. (params.json에 이 가정을 "가장 중요"라고 적었던
  주석은 틀렸고, 수정했습니다.)
- **사람 재채점이 클라우드 총비용의 97%입니다.** 양쪽이 똑같이 내는 비용이므로
  의사결정과 무관하지만, 비용을 실제로 줄이고 싶다면 GPU가 아니라
  `human_review_rate`(현재 12%)를 건드려야 합니다. 그리고 그 비율은 §1의
  채점 신뢰도가 결정합니다.

## 반드시 교체해야 하는 가정

`roi/params.json`에서 `SOURCE:QUOTE`로 표시된 값은 전부 제 추정치이며
**측정값이 아닙니다.** 특히:

| 필드 | 왜 중요한가 |
|---|---|
| `cloud.input_per_mtok` / `output_per_mtok` | 구매 결정을 단독으로 뒤집습니다 |
| `usage.active_student_ratio` (0.75) | 파일럿에서 계측해서 교체하십시오 |
| `staff.human_review_rate` (0.12) | 총비용의 대부분 |
| `local.throughput.tokens_per_second_output` | 현재 부하에선 무관하나 확장 시 필요 |

몬테카를로의 분포도 가정이지 관측이 아닙니다. 점추정의 타당성을 검증하지
않으며, 명시된 불확실성이 함의하는 폭을 정량화할 뿐입니다.
